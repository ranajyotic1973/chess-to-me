## MODIFIED Requirements

### Requirement: Move navigation uses Up/Down arrow keys instead of Left/Right arrow keys
The keyboard handler in `App.tsx` SHALL listen for `ArrowUp` (advance forward one move in the selected line) and `ArrowDown` (go back one move) instead of `ArrowRight`/`ArrowLeft`. The handler SHALL call `event.preventDefault()` on these keys and SHALL NOT fire when the chat `<TextField>` has focus.

#### Scenario: Up arrow advances to the next move
- **WHEN** a line is selected, `currentMoveIndex < moves.length - 1`, and the user presses Up arrow while the chat input is NOT focused
- **THEN** `currentMoveIndex` SHALL increment by one and the board SHALL update to the new position

#### Scenario: Down arrow goes back one move
- **WHEN** a line is selected, `currentMoveIndex > 0`, and the user presses Down arrow while the chat input is NOT focused
- **THEN** `currentMoveIndex` SHALL decrement by one and the board SHALL revert to the previous position

#### Scenario: Arrow keys do not fire when chat input is focused
- **WHEN** the user has clicked into the chat `<TextField>` and presses Up or Down
- **THEN** the default browser behavior (cursor movement within the textarea) SHALL take precedence and `currentMoveIndex` SHALL NOT change

## ADDED Requirements

### Requirement: Puzzle system prompt requests a solution array in the LLM response
When `responseType === "Puzzle"`, the system prompt generated by `systemPromptGenerator.ts` SHALL instruct the LLM to return a `solution` field containing an ordered array of moves in UCI notation alongside the FEN. The prompt SHALL specify that the FEN must be a legal chess position and that solution moves must be legal from that position.

#### Scenario: LLM receives puzzle system prompt
- **WHEN** a user asks for a chess puzzle
- **THEN** the system prompt SHALL contain explicit instructions to return `{"fen": "<valid FEN>", "solution": ["<uci_move>", ...], ...}` and to ensure every move in the solution is legal in sequence

### Requirement: LLM response parser exposes the solution field for Puzzle responses
`llmResponseParser.ts` SHALL parse and return the `solution` array from the LLM JSON response when `response_type` is `Puzzle`. The parsed solution SHALL be available as `parsedResponse.solution: string[]`.

#### Scenario: Parser returns solution array from valid response
- **WHEN** the LLM returns `{"response_type": "Puzzle", "fen": "...", "solution": ["e2e4", "d7d5"]}`
- **THEN** `parseLLMResponse` SHALL return an object where `solution` equals `["e2e4", "d7d5"]`
